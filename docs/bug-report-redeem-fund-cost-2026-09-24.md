## 一、现象与数字对账（全部实测）

2026-09-24 上午，用户从 **月月宝**（银行理财，份额型，成本单价 1.0266，最新 1.0487）
赎回 **107,321.4456 份 = ¥112,548**，出资买入新建的 **五年国债ETF**（800 份 × ¥140.685 = ¥112,548），
App 记为一条 `sell` 流水（备注「赎回购买 五年国债ETF」）。

关键证据（备份快照 vs 流水，逐项核对）：

| 项 | 09-23 | 09-24 | 差值 |
| --- | --- | --- | --- |
| 快照 totalValue | 2,285,966.30 | 2,284,538.61 | −1,427.69（正常日内波动） |
| 快照 totalCost | 2,253,991.82 | **2,256,363.62** | **+2,371.80 ← 凭空出现** |
| 明细：被赎回份额的本金 | | 107,321.4456 × 1.0266 = **110,176.20** | |
| 明细：新持仓计入成本 | | 800 × 140.685 = **112,548.00** | 差额 = **+2,371.80** |
| 已实现收益（`(price−cost)×qty`） | | (1.0487−1.0266)×107,321.4456 = **+2,371.80** | |

即：赎回腿只带走了份额的**本金（110,176.20）**，新买的目标却按**市值（112,548.00）**入成本，
组合总成本净增 **2,371.80 = 该笔赎回的浮动收益**。总收益（市值−成本）当天凭空 −2,371.80，
叠加正常波动 −1,427.69 → 用户看到 −3000+（−1,427.69 − 2,371.80 = −3,799.49，量级吻合）。

## 二、根因（代码级）

`lib/domain/transaction_service.dart` 的赎回出资路径对**份额型来源**：

```dart
// _applyRedemption（修复前）：份额型只减数量、保留单位成本，返回 0
await _updateHolding(source, quantity: (source.quantity - sourceQty)...);
return 0;
```

随后 `_applyBuy` 给目标加的是**完整金额**：

```dart
final totalCost = holding.quantity * holding.costPrice + amount; // amount = 市值
```

两条一撞：源泉侧被子份额的成本走了，目标侧却把**市值**当新本金入账
→ 差额（浮动收益）从「未实现收益」掉进「成本」，当日盈亏出现等额假亏损。

- **金额型来源**同样存隐患：`_applyCashMove` 按比例移动本金，但目标仍 +金额
  （本金≠余额时同样裂开，差额 = 该账户未实现收益）× 本次一并修。
- **已实现收益双重计数**：`PortfolioCalculator._realizedProfit` / `TradeStatsCalculator`
  把这条内部赎回 `sell` 行也按 `(price − unitCost) × qty` 计入已实现；
  成本守恒后，同一笔收益会「新持仓浮盈 + 已实现」算两遍。
- **撤销只回一半**：金额型来源的赎回流水删除时 `_reverseSell` 只回滚余额，
  本金保持减少 → 假浮盈。

与 2026-09-18 的「转账假亏损」同族：内部资金搬运（转账 / 换仓 / 赎回买新）
都必须**成本守恒**，否则当日收益出现等额假亏损。

## 三、修复（代码）

1. **`_applyRedemption`**：份额型来源返回随份额离开的本金 `sourceQty × costPrice`。
2. **`recordBuyFundedByHolding`**：目标成本只加该移动本金（`_applyBuy` 新增
   `costBasis` 参数，默认仍为金额，普通买入行为不变）。
3. **`holding_dialogs.dart` 新持仓出资流程**：创建成功后按 `movedCost ÷ 数量`
   改写份额型新持仓的成本单价（本金口径，同转账修复的「本金随钱走」）。
4. **`internal_move` 新列（schema v10→v11，默认 false）**：两条内部流程的流水
   打标 → `_realizedProfit` / `TradeStatsCalculator.realizedProfit(ByHolding)`
   全部跳过内部赎回腿；sync / backup / DAO 全链路携带。
5. **`_reverseSell` / `_reverseBuy`**：删除金额型来源赎回流水时同时还原本金；
   删除内部买入腿时按实际入账本金（`costMovedAmount`）回滚，而不是金额。
