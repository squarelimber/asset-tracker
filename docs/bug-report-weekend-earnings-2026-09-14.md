# 非交易日"当日盈亏"假涨跌 — 排查与修复报告

> **状态**：已随 **v0.9.7** 全部修复。
> 排查日期：2026-09-14 · 基线 commit `ab4e048`（v0.9.6+32）
> 方式：0.9.6 源码全链路复读 + 估值算法本地复现 + 行情接口实测 + 用户真实快照差分
> 结论标注：🔴 C=数据损坏 · 🟠 H=功能错误 · 🟡 M=口径/边缘场景

---

## 一、现象

用户在 v0.9.6 上观察到：**非交易日（周六）打开 App，"当日盈亏"会出现数百元的异常涨跌；同一数值过一会儿再看（9 点开盘后）又恢复正常。** 反复出现，无固定触发动作。

## 二、根因（已逐分钱验证）

### 2.1 同一个持仓在两条代码路径上用了两个不同的品种

| | 实时价（写"今天"这条快照） | 历史价（重建历史） |
|---|---|---|
| 来源 | `gold_fx_source.dart`：`hf_XAU` **伦敦现货金** × 美元汇率 ÷ 31.1034768 | `history_source.dart`：`InnerFuturesNewService` **上金所黄金期货 AU0** |
| 单位 | USD/盎司 → 元/克 | 元/克（期货连续合约） |

两个市场存在稳定的基差（实测约 **1%**）：`AU0` 明显高于"伦敦金折人民币"（也与上金所 Au99.99 报价偏离约 1.2%）。

### 2.2 两条路径的交汇点恰好是"今天"

回填的逐日循环为：

```dart
while (day.isBefore(todayDate)) { ... }   // history_backfill_service.dart
```

**"今天"永远不在重建范围内**，永远由另一套代码（`PortfolioCalculator` + `holdings.latestPrice` 缓存）单独写入。于是：

```
ap(“今天，实时口径”)  −  ap(“昨天，AU0 口径”)
        └── 两个品种的基差 × 持仓克数，整体落到当天
```

持仓克数为 `q` 时，该日的假涨跌 ≈ `q × (AU0 − 伦敦金折人民币)`。

### 2.3 为什么"过一会儿又正常"

下一次全量重建（启动同步合并数据后置脏 / 手动改持仓触发）会把该日按 AU0 序列重算，于是那一格被改写回正常值。两份真实备份对比可直接证实：同一天在早先备份里是一个数百元的负值，在之后的备份里已变成正常的小额利息；**两次备份重叠区间共 555 天被改写**。

时间点也对得上：备份的 `createdAt` 按写入时刻聚合后各只有两个批次——先写"今天"（单条），隔 20~40 秒全量重建历史（`[最早买入日, 今天)`），而重建时刻正好压在开盘前后。

### 2.4 修复后复算：差值为 0

用修复后的口径（伦敦现货金日线 × 当日在或之前最近的 USD/CNY 收盘 ÷ 31.1034768）重算出现异常的那一天：

```
2026-09-04   XAU=4430.96  USDCNY=6.7108  →  956.0117 元/克
备份中同日实时金价（实时路径当日实取值）     →  956.0117 元/克
差值                                         →  0.00 元/克
```

修复前同一格的历史值（AU0 口径）为 965.96 元/克，每克差 9.95 元 —— 正是那一次 700 余元异常的全部来源。修复后两条路径的值**完全一致**，该日的假涨跌归零（只剩现金类利息）。

联网校验（`live_history_sources_test.dart`）：实时报价 930.47 vs 新历史序列 929.98，相对误差 **0.053%**。

## 三、随之修复的其余缺陷

| # | 缺陷 | 等级 | 修复 |
|---|---|---|---|
| C1 | 行情刷新失败仍无条件 `ensureTodaySnapshot(force: true)`，用缓存旧价重写当天 | 🔴 C | 刷新结果有失败项时不重写；历史回填因抓取失败中止时同样不重写（`BackfillResult.historyUnavailable`） |
| H1 | 快照 `createdAt` 带 DB 默认值且 companion 未传 → `insertOnConflictUpdate` 不回写版本；而它正是跨设备 LWW 的版本字段 | 🟠 H | 每次写入显式提供时间戳，修正值可参与合并决胜 |
| H3 | `MarketSession` 计算了但全项目零引用：休市/开盘前的行情涨跌幅仍被当作"今天" | 🟠 H | 迁到 `core/market_session.dart` 并新增 `quoteChangeIsToday`，按行情源判定（A 股/基金/黄金/汇率 vs 加密货币） |
| M1 | `todayEarningOf` 无条件假定最后一条快照是今天 | 🟡 M | 校验 `snapshots.last.date == todayKey(now)`，否则返回 null |
| M2 | 同一张卡片里"总资产"是实时、"今日盈亏"是快照差值，时点不一致 | 🟡 M | 优先快照口径；当天快照缺失时回落到与"总资产"同一时点的实时数值 |

## 四、修复内容

1. **统一黄金口径（主因）**：新增 `lib/core/gold.dart`，把"盎司→克"与换算公式收敛为单一定义，实时报价（native 的 `GoldFxSource`、web 的 `TencentGoldFxAdapter`）与历史序列（`XauGoldHistorySource`）共用。历史序列改由 **XAU 日线收盘 × 当日在或之前最近的 USD/CNY 收盘 ÷ 31.1034768** 生成（黄金与外汇交易日历不同，按日期前向填充汇率）。
2. **"今天"与历史同源**：回填窗口改为 `[最早买入日, 今天]`，且轻量运行也会重算当天；实时路径的写入仅作为无法回填（Web）或历史抓取失败时的兜底。
3. **一次性全量重算**：回填标记升级为 `backfill_v7_gold_spot_and_today`，升级后所有设备自动按新口径重算一次。
4. **刷新/抓取失败保护**：失败时既不写也不改当天快照。
5. **交易日语义接入**：休市与开盘前的行情涨跌幅不再被展示为"今天"的盈亏。

## 六、已知残留（未在本次处理）

- **快照本质是派生数据，却参与跨设备 last-write-wins**。本次修好了"修正值无法取胜"（版本字段回写）与"用陈旧价格重写"（刷新失败保护），但离线设备仍可能以更晚的写入时间提交一份基于旧行情的值。彻底解法是让快照不参与 LWW，而由每台设备用本机行情重建（Web 端无法回填，需要额外方案）。
- **场外基金"最新净值"滞后一个交易日**：实测盘中拿到的"最新净值"仍是上一交易日。实时路径与历史路径读的是同一个滞后值，因此**不产生跨日跳变**（收益归属由回填按净值日期修正），故本次未改。接口响应中已带净值日期 `FSRQ`，后续可据此把抓取日与净值日解耦。
- **无节假日历**：仅按周末判定休市，法定假日仍会被视为交易日（`quoteChangeIsToday` 依据同一判定）。
