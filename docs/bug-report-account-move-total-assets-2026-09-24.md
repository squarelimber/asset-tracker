排查对象：用户反馈「仅仅是变更账户所属（从支付宝改到兴业证券）就会导致整个资产出现变化，
包括趋势图，现在这个 app 已经处于无法使用的状态」。数据：`asset_tracker_2026-09-24.json`。

## 修复状态（v0.9.22）

| # | 问题 | 状态 |
| --- | --- | --- |
| 1 | 份额型**平滑持仓**（银行理财等手动净值产品）历史估值用「当前份数」→ 部分赎回后任一**全量重建**都会让整个趋势塌掉 | ✅ 已修（按流水重放份额+成本） |

## 一、先澄清：变更账户本身是「无害」的

总资产 = Σ 各持仓「数量 × 最新价」，**账户只是存放持仓的容器**，没有余额概念。
把持仓从支付宝挪到兴业证券，持仓的数量/成本/市值一行都没变 → 总资产、趋势图
**理论上一分钱都不该动**（账户页里两个账户各自的汇总会变，那是正常的）。

你看到的全盘变化，真正的元凶是「这次编辑触发了历史回填，而回填做了全量重建」。

## 二、真正的根因（代码级）

历史回填对**份额型平滑持仓**（`bank_wealth` 且 marketSource 为手动/汇率，如月月宝 JY040214、
多月宝 JY040307）的每一天估值，用的是：

```dart
// history_backfill_service.dart（修复前）
value = h.quantity * price;        // h.quantity = 当前份数，全历史每一天都一样！
```

完全忽略买卖流水。2026-09-24 你赎回了月月宝 **107,321.4456 份**（223,522.61 → 116,201.16），
此后只要做一次**全量重建**（设置→重建历史快照，或备份恢复/换设备后首次打开——backup 不携带
settings，重建标记丢失 → 下次回填自动升级为全量），**从 2025-03-01 到 09-23 的每一天**都会被
按赎回后的 116,201.16 份重新估值：

- 总资产每天少 ≈ 107,321 × ~1.04 ≈ **−112,548**
- 总成本每天少 ≈ 107,321 × 1.0266 ≈ **−110,176**

用你备份里的数字实测：09-23 快照 总资产 2,285,966 / 总成本 2,253,991，修复前全量重建后
会变成 ≈ 2,173,418 / 2,143,816——**整条净值曲线塌掉 11 万**，收益日历、区间统计、日明细
全部跟着错。这就是「整个资产出现变化 + 趋势图 + app 无法使用」。

> v8 修复（0.9.11）已经让**行情类**份额持仓按流水重放（`HoldingReplay`），但平滑分支在
> 代码里更靠前、直接 `continue`，把银行理财这类「没有行情、用插值」的持仓漏掉了——
> 文档里当时假设「份额型银行理财实际没有流水」，这次被月月宝的真实赎回打破了。

## 三、修复（v0.9.22）

1. `history_backfill_service.dart` / `holding_details.dart` / `product_earnings_service.dart`
   三处口径统一：份额型平滑持仓同样用 `HoldingReplay` 按流水重放逐日份额与成本
   （无流水的持仓回放结果 = 当前持仓，行为与原来完全一致；有部分赎回/清仓时才体现差异）。
2. 新增一次性重建标记 `backfill_v9_smooth_share_replay`：老库（v7/v8 已跑过）装上修复版后
   首次打开会自动做一次全量重建，把已塌掉的曲线按回放份额补回。标记只影响迁移这一次，
   之后恢复 light 窗口。

## 四、验证

- `flutter analyze`：0 issues
- 全量 `flutter test`：全绿。新增 `test/smooth_share_replay_test.dart` 4 条：
  ① 回填：赎回日前保持赎回前份额、赎回日起用剩余份额（旧行为在赎回前用 60 份 → 用例失败）

## 五、你需要做的（装 v0.9.22 之后）

1. **不用手动改任何东西**：v9 标记会让首次打开（联网时）自动全量重建一次，趋势图按回放份额
   自动恢复。若不放心，也可以在 设置 → 重建历史快照 手动跑一次（收盘后执行）。
2. 之前 09-24「月月宝 → 五年国债ETF」那笔的成本修复仍然要做（国债ETF 成本单价
   **140.685 → 137.7202450653**，或删掉重录），否则今天/本月的收益仍会差 +2,371.80。
3. 变更账户所属可以放心用：它只改容错归属，不动任何数值；唯一的影响是那笔流水
   仍挂在旧账户下（显示层面，不影响计算）。

## 六、残留与已知边界

1. 平滑份额持仓的**价格**仍用「成本 → 最新价」几何插值（没有真实净值序列），
   本次只修了**份额/成本**的每日还原——价格形态不变。
2. 已塌陷且已把错误快照同步到其他设备的用户，修复版全量重建会在各自设备上各自修复
   （last-write-wins 会把重建后的正确值合并过去）。
